# Nekobo Firmware

This folder contains the microcontroller firmware for Nekobo (Arduino sketch).

Summary
- Location: `software/firmware/nekobo_v0_1_fw`
- Purpose: control motors, LEDs, sensors and respond to the ASCII line protocol used by the RP4 middleware.

Quick notes
- The authoritative protocol definition lives at `software/tools/protocol_setting.json`.
- Run `python3 software/tools/sync_protocol.py` to regenerate `protocol.h` and the middleware runtime mapping.

Build & flash
1. Use `arduino-cli` or the Arduino IDE to compile and upload `nekobo_v0_1_fw.ino`.
2. Ensure `protocol.h` is present (generated by `sync_protocol.py`).

Testing firmware from a PC (without the RP4 application)

You can test the firmware over a serial connection from your PC without running the RP4 middleware or the full `nekobo_main` application. This is useful when developing firmware or validating behavior.

1) Connect the Arduino to your PC and identify the serial device (example `/dev/ttyACM0` or `COM3`).

2) Open a simple serial console (example using `socat` on Linux):

```bash
# connect interactive: substitute your serial device and baud
socat -,raw,echo=0,escape=0x03 /dev/ttyACM0,raw,echo=0,crnl,baud=57600
```

3) Manual ASCII commands (wire format: `<ID_HEX> [args]\n`):

- Request heartbeat (firmware will reply with `HEARTBEAT_RESP`):

  echo -e "0x10\n" > /dev/ttyACM0

  Expected reply example:
  ```text
  0x82 123 5
  ```
  - `0x82` is `HEARTBEAT_RESP` (init_ms loop_ms).
  - The D13 LED toggles on each heartbeat.

- Set LED (RGB):

  echo -e "0x03 255 0 128\n" > /dev/ttyACM0

  Expected reply:
  ```text
  ACK 0x03
  ```

- Move motors (left right):

  echo -e "0x01 120 -120\n" > /dev/ttyACM0

  Expected reply:
  ```text
  ACK 0x01
  ```

4) Notes and debugging
- If you see `NACK` responses, check argument counts and ranges.
- The firmware prints `Nekobo firmware ready` on startup — monitor the serial console for it.
- The firmware uses `MSG_*` macros from `protocol.h` for IDs; regenerate via `sync_protocol.py` if you change the authoritative protocol.

Safety
- Be careful when commanding motors directly; test with wheels off the ground until behavior is validated.

Troubleshooting
- If serial prints look garbled, confirm baud rate is 57600.
- If `protocol.h` is out of sync after editing `protocol_setting.json`, run `python3 software/tools/sync_protocol.py` and recompile firmware.
